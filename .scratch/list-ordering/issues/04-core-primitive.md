# 04 — Ядро: трейт, Positioner, placeInto(), guard, Positioned

**What to build:** единственный примитив размещения — один код-путь для перестановки внутри списка и переноса между списками (Т2), с полным разрешением якорей, guard'ом против записи мимо примитива и событием с корректными `from`/`to`. Это самый крупный тикет пакета — по конструкции: разрезать его по типу перемещения запрещено требованиями (Т2).

**Blocked by:** 03

**Status:** ready-for-agent

- [x] `Concerns\HasOrdering` — `currentGroupKey()` читает `getOriginal()` объявленных колонок, не изменённые в памяти значения; `placeInto(GroupKey $group, ?Orderable $after, ?Orderable $before): void` работает одинаково на новой модели (`exists === false` — вычисляет ранг и вставляет одним `save()`) и на персистентной (`exists === true` — перемещает)
- [x] `orderingGroupColumns()` объявлен `abstract` в самом трейте (не только в контракте) — использование трейта без контракта не компилируется
- [x] `placeInto()` валидирует набор колонок переданного `GroupKey` на точное совпадение с `orderingGroupColumns()` — иначе `InvalidGroupKeyException` (из тикета 02)
- [x] `Exceptions\InvalidAnchorException` — якорь, не принадлежащий целевой группе (сравнение через его `currentGroupKey()`), бросается при явно переданных обоих якорях
- [x] Внутренний `Positioner` — правила разрешения якорей: оба заданы явно → используются как границы без проверки смежности (нужно для восстановления из корзины: между старыми соседями могли вставить новые элементы); задан только `$after` → `$before` резолвится как следующий элемент после `$after` в целевой группе; задан только `$before` → `$after` резолвится как элемент перед `$before`; ни один не задан → трактуется как «в конец группы» (`$after` = текущий последний элемент, `ORDER BY rank DESC LIMIT 1`); пустая группа → оба остаются `null`, ранг берётся из затравки генератора
- [x] `bootHasOrdering()` — `saving`-guard: если `exists === true` и колонки группы/ранга dirty без внутреннего флага обхода — `GuardedColumnMutationException`; `create()`/фабрики/сидеры с явным рангом не блокируются (guard применяется только к обновлению уже персистентной записи)
- [x] Narrowing `?Orderable` → `Model&Orderable` на границе трейт↔`Positioner` — через явный `throw`, **не** `assert()` (в проде `zend.assertions=-1` компилирует `assert()` в ничто — тихий no-op narrowing пропустит не-`Model` объект к `getOriginal()`/`save()`)
- [x] Флаг обхода guard'а снимается в `finally` — исключение внутри `placeInto()` не должно оставлять модель без защиты до конца запроса
- [x] `Events\Positioned` — `$model`, `$from` (пре-мутационный `GroupKey`, через `currentGroupKey()` до записи новых колонок в память), `$to`; диспатчится после успешного `save()`
- [x] Тест: смена колонок группы и запись нового ранга — одна SQL-операция (Т4), промежуточного состояния не существует
- [x] Тест (инвариант нетронутых рангов): список из N элементов, снимок рангов всех кроме перемещаемого до операции, `placeInto()`, повторный снимок по тем же ID — `assertSame` поэлементно
- [x] Тест: `Positioned::$from !== $to` на кросс-групповом переносе — ловит наивную реализацию `currentGroupKey()`, читающую уже изменённые in-memory атрибуты вместо `getOriginal()`
- [x] Тесты на все восемь сценариев §8 ТЗ (пустой список, между соседями, реордер внутри списка, перенос между списками между элементами, перенос в пустой список, «после X» где X сменил группу, «после X» где X удалён но известен Y, ни один якорь не известен) и все три формы группировки §7 (составной ключ, одна колонка, пустой список колонок) — для §7 пустого списка колонок понадобилась третья фикстура (`WishlistItem`), т.к. тикет 03 покрывал этот случай только на чтении (`scopeOrdered`), а `placeInto()` валидирует набор колонок модели буквально
- [x] Тест: два явно переданных несмежных якоря (между ними уже есть другие элементы) — ранг всё равно генерируется строго между границами
- [x] Тест guard'а: прямая запись + `save()` на персистентной модели → `GuardedColumnMutationException`; тот же путь через `placeInto()` не бросает; `create()`/фабрика с явным рангом не бросает

**Находки сверх чеклиста:**
1. Изначально `Positioner` вызывал `$model->withOrderingGuardBypassed()` — публичный метод трейта. PHPStan не мог статически подтвердить существование этого метода на типе `Model&Orderable` (метод объявлен трейтом, а не контрактом `Orderable`). Решение: guard снимается в `HasOrdering::placeInto()` вокруг всего вызова `Positioner` (резолюция якорей всё равно только читает), а `withOrderingGuardBypassed()` стал `private` — публичной лазейки на модели больше нет вообще.
2. Аналогичная проблема с возвратными типами `findNext()/findPrevious()/findLast()` (Eloquent `Builder::first()` не знает про `Orderable`) — решена тем же приёмом explicit-throw narrowing (`narrowResult()`), что и на границе трейт↔`Positioner`, а не через `@var`/касты.
3. Гейт словаря (ярус 1, «placement») дважды ловил собственные докблоки/имена тестов пакета («The only placement primitive», «...after a placement») — переформулировано без буквального слова.

**Пост-ревью правка (Standards-ось):** `narrowAnchor()` бросал общий `ListOrderingException` при передаче не-Eloquent якоря — по смыслу это ровно случай «невалидный якорь», приведено к `InvalidAnchorException` для консистентности таксономии исключений. `narrowResult()` в `Positioner` (структурно недостижимая ветка, дублирующая паттерн narrowing) сознательно оставлен на общем исключении — ревью отметило это как приемлемое, отдельного якоря там нет.
