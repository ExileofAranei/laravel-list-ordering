# 04 — Ядро: трейт, Positioner, placeInto(), guard, Positioned

**What to build:** единственный примитив размещения — один код-путь для перестановки внутри списка и переноса между списками (Т2), с полным разрешением якорей, guard'ом против записи мимо примитива и событием с корректными `from`/`to`. Это самый крупный тикет пакета — по конструкции: разрезать его по типу перемещения запрещено требованиями (Т2).

**Blocked by:** 03

**Status:** ready-for-agent

- [ ] `Concerns\HasOrdering` — `currentGroupKey()` читает `getOriginal()` объявленных колонок, не изменённые в памяти значения; `placeInto(GroupKey $group, ?Orderable $after, ?Orderable $before): void` работает одинаково на новой модели (`exists === false` — вычисляет ранг и вставляет одним `save()`) и на персистентной (`exists === true` — перемещает)
- [ ] `orderingGroupColumns()` объявлен `abstract` в самом трейте (не только в контракте) — использование трейта без контракта не компилируется
- [ ] `placeInto()` валидирует набор колонок переданного `GroupKey` на точное совпадение с `orderingGroupColumns()` — иначе `InvalidGroupKeyException` (из тикета 02)
- [ ] `Exceptions\InvalidAnchorException` — якорь, не принадлежащий целевой группе (сравнение через его `currentGroupKey()`), бросается при явно переданных обоих якорях
- [ ] Внутренний `Positioner` — правила разрешения якорей: оба заданы явно → используются как границы без проверки смежности (нужно для восстановления из корзины: между старыми соседями могли вставить новые элементы); задан только `$after` → `$before` резолвится как следующий элемент после `$after` в целевой группе; задан только `$before` → `$after` резолвится как элемент перед `$before`; ни один не задан → трактуется как «в конец группы» (`$after` = текущий последний элемент, `ORDER BY rank DESC LIMIT 1`); пустая группа → оба остаются `null`, ранг берётся из затравки генератора
- [ ] `bootHasOrdering()` — `saving`-guard: если `exists === true` и колонки группы/ранга dirty без внутреннего флага обхода — `GuardedColumnMutationException`; `create()`/фабрики/сидеры с явным рангом не блокируются (guard применяется только к обновлению уже персистентной записи)
- [ ] Narrowing `?Orderable` → `Model&Orderable` на границе трейт↔`Positioner` — через явный `throw`, **не** `assert()` (в проде `zend.assertions=-1` компилирует `assert()` в ничто — тихий no-op narrowing пропустит не-`Model` объект к `getOriginal()`/`save()`)
- [ ] Флаг обхода guard'а снимается в `finally` — исключение внутри `placeInto()` не должно оставлять модель без защиты до конца запроса
- [ ] `Events\Positioned` — `$model`, `$from` (пре-мутационный `GroupKey`, через `currentGroupKey()` до записи новых колонок в память), `$to`; диспатчится после успешного `save()`
- [ ] Тест: смена колонок группы и запись нового ранга — одна SQL-операция (Т4), промежуточного состояния не существует
- [ ] Тест (инвариант нетронутых рангов): список из N элементов, снимок рангов всех кроме перемещаемого до операции, `placeInto()`, повторный снимок по тем же ID — `assertSame` поэлементно
- [ ] Тест: `Positioned::$from !== $to` на кросс-групповом переносе — ловит наивную реализацию `currentGroupKey()`, читающую уже изменённые in-memory атрибуты вместо `getOriginal()`
- [ ] Тесты на все восемь сценариев §8 ТЗ (пустой список, между соседями, реордер внутри списка, перенос между списками между элементами, перенос в пустой список, «после X» где X сменил группу, «после X» где X удалён но известен Y, ни один якорь не известен) и все три формы группировки §7 (составной ключ, одна колонка, пустой список колонок)
- [ ] Тест: два явно переданных несмежных якоря (между ними уже есть другие элементы) — ранг всё равно генерируется строго между границами
- [ ] Тест guard'а: прямая запись + `save()` на персистентной модели → `GuardedColumnMutationException`; тот же путь через `placeInto()` не бросает; `create()`/фабрика с явным рангом не бросает
