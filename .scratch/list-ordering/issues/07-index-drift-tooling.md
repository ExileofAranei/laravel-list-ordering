# 07 — Инструменты проверки индекса

**What to build:** способ поймать расхождение между `orderingGroupColumns()` модели и фактическим уникальным индексом в БД — вручную, по расписанию консьюмера (в его CI или руками), не как рантайм-проверку на живом запросе.

**Blocked by:** 03

**Status:** ready-for-agent

- [x] Artisan-команда `list-ordering:check-index {model?} {--all}` — сравнивает `orderingGroupColumns()` + `orderingRankColumn()` модели с фактическим составом уникального индекса через интроспекцию схемы драйвера (`Schema::getIndexes()`, доступно с Laravel 11 — минимальной поддерживаемой версии пакета)
- [x] `Testing\AssertsOrderingIndex::assertOrderingIndexMatches(string $modelClass): void` — та же проверка как ассерт для тестового набора консьюмера
- [x] Никакой ленивой/рантайм-проверки при первом `placeInto()` — только явный вызов команды/ассерта (проверка живёт в `Internal\IndexInspector`, которым команда и трейт пользуются одинаково — одна реализация сравнения, а не две расходящиеся)
- [x] Тест: команда/ассерт проходят на фикстурной модели с корректным индексом (обе фикстуры — составной ключ и одна колонка)
- [x] Тест: команда/ассерт ловят расхождение — намеренно рассинхронизированные `orderingGroupColumns()` и индекс фикстурной таблицы дают явную ошибку с именами недостающих/лишних колонок (новая фикстура `MisconfiguredEntry`, смотрит на существующую таблицу `shopping_list_entries` с заведомо неверными группирующими колонками)

**Находка:** `--all` (сканирование `app_path()` на классы, реализующие `Orderable`) — best-effort механизм, не тестируется в наборе пакета: testbench не имеет реалистичного `app/` с моделями потребителя для сканирования, это функциональность специфично для приложения-потребителя. Задокументировано прямо в докблоке метода.

**Пост-ревью правка:** `Testing\AssertsOrderingIndex` дал тот же `trait.unused` false positive в PHPStan, что и `HasOrdering` в тикете 03 — расширен существующий `ignoreErrors` на `src/Testing/*.php`.

**Пост-ревью правка (Standards-ось):** при нескольких уникальных индексах, содержащих колонку ранга, и ни одном точном совпадении, `IndexInspector` молча выбирал первый кандидат для отчёта — какой индекс драйвер БД вернёт первым, решает не разработчик. Теперь диф репортится по каждому кандидату отдельно, по имени.
