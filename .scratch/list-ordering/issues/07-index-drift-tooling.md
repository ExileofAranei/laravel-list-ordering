# 07 — Инструменты проверки индекса

**What to build:** способ поймать расхождение между `orderingGroupColumns()` модели и фактическим уникальным индексом в БД — вручную, по расписанию консьюмера (в его CI или руками), не как рантайм-проверку на живом запросе.

**Blocked by:** 03

**Status:** ready-for-agent

- [ ] Artisan-команда `list-ordering:check-index {model?} {--all}` — сравнивает `orderingGroupColumns()` + `orderingRankColumn()` модели с фактическим составом уникального индекса через интроспекцию схемы драйвера
- [ ] `Testing\AssertsOrderingIndex::assertOrderingIndexMatches(string $modelClass): void` — та же проверка как ассерт для тестового набора консьюмера
- [ ] Никакой ленивой/рантайм-проверки при первом `placeInto()` — только явный вызов команды/ассерта
- [ ] Тест: команда/ассерт проходят на фикстурной модели с корректным индексом
- [ ] Тест: команда/ассерт ловят расхождение — намеренно рассинхронизированные `orderingGroupColumns()` и индекс фикстурной таблицы дают явную ошибку с именами недостающих/лишних колонок
