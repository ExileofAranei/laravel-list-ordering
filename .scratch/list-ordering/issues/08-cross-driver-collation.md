# 08 — Кросс-драйверная проверка коллаций

**What to build:** доказательство (не декларация), что сортировка ранга в БД побайтово совпадает с сортировкой в PHP на каждом реально поддерживаемом драйвере — самый рискованный пункт пакета, потому что SQLite зелёный независимо от того, что делает драйверная ветка макроса.

**Blocked by:** 03

**Status:** ready-for-agent

- [ ] CI workflow: service-контейнеры MySQL, MariaDB, PostgreSQL — тестовый прогон запускается на каждом из них плюс SQLite
- [ ] Тест сортировки: набор рангов вставляется через `FractionalRankGenerator` напрямую в фикстурную таблицу (без `placeInto()` — это тот случай, где guard из тикета 04 не мешает, поскольку речь о создании, не обновлении), затем `Model::orderBy(rank)->pluck(rank)` сравнивается с тем же набором значений, отсортированным в PHP байтовым сравнением (`strcmp`/`SORT_STRING`)
- [ ] Тест помечен группой/тегом, специфичным для коллации, и на SQLite явно skip'ается с сообщением («SQLite побайтово сравнивает по умолчанию независимо от ветки макроса — не валидирует драйверный синтаксис»), а не молча проходит
- [ ] Проверка синтаксиса макроса для каждого драйвера: MySQL/MariaDB реально создают колонку с `charset('binary')`, PostgreSQL — с `collation('C')` (интроспекция схемы после миграции, не только косвенно через сортировку)
