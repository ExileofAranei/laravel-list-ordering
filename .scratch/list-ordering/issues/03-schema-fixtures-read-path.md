# 03 — Схема, фикстуры и путь чтения

**What to build:** таблица с рангами, которую можно наполнить напрямую (без `placeInto()`) и прочитать в порядке. Ни этот тикет, ни его тесты не касаются размещения/перемещения — только хранение и чтение.

**Blocked by:** 02

**Status:** ready-for-agent

- [x] `Blueprint::orderingRank(string $column = 'rank')` — макрос, регистрируется провайдером; колонка 64 символа; MySQL/MariaDB — `charset('binary')`; PostgreSQL — `collation('C')`; SQLite — `collation()` не вызывается вовсе (не `collation(null)`)
- [x] Фикстурные модели и миграции пакета — намеренно посторонний домен (`SpiceJar`/`spice_jars`, `ShoppingListEntry`/`shopping_list_entries`), не пересекается ни с README-примерами (канбан/галерея/лендинг), ни с доменом консьюмера; две фикстурные модели/таблицы: `SpiceJar` — составной ключ из двух not-null колонок (`pantry_id`, `shelf`), `ShoppingListEntry` — одна колонка (`list_id`); пустой список колонок (`[]`) проверяется на `ShoppingListEntry` через отдельный тестовый сценарий (`GroupKey::of([])` как глобальный список), без отдельной таблицы
- [x] Составной уникальный индекс (колонки группы + `rank`) на каждой фикстурной таблице — дополнительно покрыт тестом, что дубликат (группа+ранг) реально ловится `QueryException`
- [x] `HasOrdering::scopeOrdered(Builder $query, ?GroupKey $group = null): Builder` — с `$group` применяет `$group->applyTo()` + `orderBy(rank)`; без `$group` — только сортировка, PHPDoc прямо оговаривает, что порядок между разными группами в результате не гарантирован
- [x] `HasOrdering::orderingRankColumn(): string` — метод (не свойство), по умолчанию `'rank'`, переопределяется обычным перекрытием в модели
- [x] Тест: две независимые группы в одной фикстурной таблице, ранги расставлены напрямую (без `placeInto()`); `Model::ordered()->get()` без `GroupKey` — порядок внутри каждой группы корректен (`assertSame`), между группами ничего не утверждается
- [x] Тест: `Model::ordered(GroupKey::of([...]))` — фильтрует ровно нужную группу и сортирует (проверено на обеих фикстурах — одна колонка и составной ключ)

**Находки сверх чеклиста:**
1. `getEnvironmentSetUp()` в testbench выполняется **до** boot() провайдеров пакета — миграции фикстур, вызванные там, падали на `Blueprint::orderingRank()` (макрос ещё не зарегистрирован). Перенесено в `TestCase::setUp()` после `parent::setUp()`.
2. PHPStan (level 5, только `src/`+`database/` в `paths`) ожидаемо репортил `HasOrdering` как `trait.unused` — трейт используется только моделями консьюмера, которых анализ пакета никогда не увидит. Добавление `tests/` в `paths` для решения этого вскрыло ~20 несвязанных ложных срабатываний на Pest-специфичном флюентном API (`TestCall::$generator`), для которого в проекте нет специальной PHPStan-интеграции — это отдельная задача, не относящаяся к тикету 03. Вместо этого — точечный `ignoreErrors` на `identifier: trait.unused` для `src/Concerns/*.php` с обоснованием в комментарии.
