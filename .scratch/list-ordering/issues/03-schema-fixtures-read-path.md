# 03 — Схема, фикстуры и путь чтения

**What to build:** таблица с рангами, которую можно наполнить напрямую (без `placeInto()`) и прочитать в порядке. Ни этот тикет, ни его тесты не касаются размещения/перемещения — только хранение и чтение.

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] `Blueprint::orderingRank(string $column = 'rank')` — макрос, регистрируется провайдером; колонка 64 символа; MySQL/MariaDB — `charset('binary')`; PostgreSQL — `collation('C')`; SQLite — `collation()` не вызывается вовсе (не `collation(null)`)
- [ ] Фикстурные модели и миграции пакета — намеренно посторонний домен, не пересекается ни с README-примерами (канбан/галерея/лендинг), ни с доменом консьюмера; для проверки всех трёх форм группировки из ТЗ нужно минимум две фикстурные модели/таблицы: одна с составным ключом из двух not-null колонок, одна с одной колонкой; пустой список колонок (`[]`) проверяется на одной из них через отдельный тестовый сценарий, не отдельной таблицей
- [ ] Составной уникальный индекс (колонки группы + `rank`) на каждой фикстурной таблице
- [ ] `HasOrdering::scopeOrdered(Builder $query, ?GroupKey $group = null): Builder` — с `$group` применяет `$group->applyTo()` + `orderBy(rank)`; без `$group` — только сортировка, PHPDoc прямо оговаривает, что порядок между разными группами в результате не гарантирован
- [ ] `HasOrdering::orderingRankColumn(): string` — метод (не свойство), по умолчанию `'rank'`, переопределяется обычным перекрытием в модели
- [ ] Тест: две независимые группы в одной фикстурной таблице, ранги расставлены напрямую (без `placeInto()`); `Model::ordered()->get()` без `GroupKey` — порядок внутри каждой группы корректен (`assertSame`), между группами ничего не утверждается
- [ ] Тест: `Model::ordered(GroupKey::of([...]))` — фильтрует ровно нужную группу и сортирует
