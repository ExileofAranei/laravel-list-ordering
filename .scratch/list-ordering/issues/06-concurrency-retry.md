# 06 — Конкурентность: ретрай с перерезолюцией якорей

**What to build:** конфликт уникального индекса при параллельной вставке в один и тот же промежуток не падает пользователю — вызывается ограниченный ретрай, который каждый раз заново резолвит соседей из БД.

**Blocked by:** 04

**Status:** ready-for-agent

- [ ] `Positioner` принимает `maxRetries` параметром конструктора (не конфиг-файл), значение по умолчанию — 3; переопределяется биндингом в контейнере
- [ ] На конфликт уникальности при записи — повтор до `maxRetries` раз; **каждая** попытка заново резолвит недостающие якоря SELECT'ом по индексу, а не перегенерирует ранг между границами предыдущей попытки (переиспользование старых границ детерминированно воспроизвело бы тот же конфликт — это условие сходимости, не оптимизация)
- [ ] Исчерпание ретраев → `Exceptions\RankConflictException`
- [ ] Тест: форсированный конфликт на первой попытке (тестовый дубль `RankGenerator`, возвращающий уже занятый ранг один раз) — операция успешно завершается через ретрай
- [ ] Тест: ретрай действительно перерезолвит якорей заново (не просто перегенерирует ранг в тех же границах) — например, через подмену состояния соседей между попытками и проверку итогового результата
